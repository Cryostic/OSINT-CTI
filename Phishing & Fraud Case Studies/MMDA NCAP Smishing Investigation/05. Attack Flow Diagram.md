# 05. Attack Flow Diagram

##  Step-by-Step Narrative

### Phase A — Preparation (inferred, unobserved)
1. **Theme selection:** Operators track Philippine news cycles; the NCAP story was highly visible in 2025-2026 (relaunch May 2025; SC partially lifting TRO; July 2026 SC ruling; eGovPH integration July 2026). An active, unfamiliar, and newly newsworthy enforcement program is the ideal smishing hook. (Assessment — High for the general mechanism; Low for proving this operator's intent.)
2. **Template construction:** Localized Taglish copy mirroring official notice language ("directive", "grace period", "settlement") with fabricated urgency.
3. **Infrastructure:** register cheap look-alike domain (`ncapmmda.skin`) + prepare landing page (unobserved); arrange SMS sending path (aggregator/grey route/IMSI catcher — per Smart/PLDT disclosures, all are observed techniques in PH).

### Phase B — Delivery (confirmed in this case)
4. SMS sent with sender identifier `el-mashharawi@live[.]de`; received 2026-08-13 10:51 AM. Sender ID displayed as an email address — a channel-selection artifact that contradicts MMDA's registered `MMDA_NCAP` sender ID.

### Phase C — Persuasion (confirmed in this case)
5. The text executes the 4-step playbook: **authority → violation → deadline → action**. The 13-hour window (Aug 13, 10:51 AM → Aug 14) suppresses verification behavior (thinking in terms of "I might have been caught on CCTV" — unfalsifiable for non-drivers too, since no details are given).

### Phase D — Outcomes (depends on victim behavior)
6. **No engagement (this case):** chain terminates; no technical compromise.
7. **Reply "Y":** likely confirms a live number to the operator for follow-up lures (Assessment — Medium; reply-tracking is common in this family, and MMDA advisories explicitly state genuine notices never request replies).
8. **Click:** victim lands on the phishing page (H1 most likely): fake violation lookup → fake payment → credential/e-wallet theft (as warned by MMDA Chair Artes, Aug 2026). Downstream impacts: unauthorized transactions, account takeover, identity-fraud data reuse.

### Phase E — Post-incident (recommended for any victim)
9. Containment: block sender, delete message, no further interaction.
10. If engaged with the page: rotate credentials used there, contact bank/e-wallet immediately, monitor statements, file report with NBI/PNP-ACG and the e-wallet/bank fraud teams.
11. Reporting + sharing the pattern to reduce the blast radius (see `06. Reporting.md`).

## Key Branch Points for Detection

| # | Branch | Detectable signal | Detection material |
|---|---|---|---|
| B-1 | SMS arrival | Sender ≠ `MMDA_NCAP` + NCAP theme + link | SMS/email gateways, user reporting; Sigma (I-3/I-4) |
| B-2 | Reply "Y" | Reply-to-scam traffic; telco-side flagging | User education; telco filters |
| B-3 | Link engagement | DNS/proxy hit to `ncapmmda[.]skin` or `*.skin` + NCAP-related referrer | Sigma DNS/proxy rules (`08. Detection Content.md`) |
| B-4 | Data entry | Form-fill on phishing page (hard to detect network-side) | YARA on captured pages; e-wallet/bank fraud monitoring |
