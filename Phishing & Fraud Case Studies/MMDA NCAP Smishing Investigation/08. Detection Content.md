# 08. Detection Content

> Detection engineering artifacts for the NCAP smishing campaign family (case `PH-SMISH-2026-0813-NCAP-001`). Default format is **Sigma** (platform-agnostic); a YARA rule is included for phishing-page content capture. Tune noise thresholds to your environment — see false-positive notes on each rule.

---

## Sigma Rule — NCAP/MMDA Government-Impersonation Smishing (Email/Mail Gateway)

Catches lure messages that impersonate MMDA/NCAP with settlement language and an embedded link, using **condition combinations** to suppress ordinary informational content.

```yaml
title: NCAP-MMDA Government Impersonation Smishing
id: 6f3d9c2e-4b1a-4f8e-9d2c-1a2b3c4d5e6f
status: experimental
description: >
  Detects smishing/phishing messages referencing the MMDA No Contact
  Apprehension Policy (NCAP) combined with settlement language, deadline
  pressure, and an embedded external link. Legitimate MMDA NCAP notices
  never contain payment links or reply requests. Campaign family observed
  Feb/Aug 2026; case PH-SMISH-2026-0813-NCAP-001.
references:
  - https://pia.gov.ph/news/mmda-warns-public-vs-fake-ncap-text-scams-urges-caution-before-sharing-online-content
  - https://newsinfo.inquirer.net/2267206/mmda-dont-fall-for-ncap-text-scams
author: Vanguard (CTI)
date: 2026-08-13
logsource:
    category: email
    product: generic
    definition: 'Mail gateway logs with subject/body extraction; adapt product field for mimecast/defender/mailgate'
detection:
    selection_agency:
        - subject|contains|all:
            - 'NCAP'
            - 'MMDA'
        - body|contains|all:
            - 'ncap'
            - 'mmda'
    selection_lure:
        body|contains|any:
            - 'settlement required'
            - 'grace period'
            - 'mandatory additional charges'
            - 'settle this before'
            - 'reply of Y'
            - 'reply y'
            - 'mag-reply ng y'
            - 'pakisettle'
            - 'may huli ka'
    selection_link:
        - body|contains|any:
            - 'http'
            - 'https'
        - attachments: false
    selection_sender_anomaly:
        sender|re: '(@live\.[a-z]+|@gmail\.[a-z]+|@yahoo\.[a-z]+)'  # non-gov email-looking sender
    condition: selection_agency and selection_lure and selection_link
falsepositives:
    - Forwarded legitimate news articles or social-media posts about NCAP scams (raise threshold by adding selection_sender_anomaly for mail logs).
    - Citizen-education campaigns quoting the scam (exclude known safe senders / mailing lists).
level: medium
tags:
    - attack.initial-access
    - attack.t1566.002
    - attack.reconnaissance
    - attack.t1598.003
    - attack.defense-evasion
    - attack.t1656
```

**Tuning note:** For **SMS** telemetry (if your SIEM ingests SMS gateway logs), map the same fields to the SMS sender field and body; the official sender `MMDA_NCAP` must be excluded (`sender != 'MMDA_NCAP'`), mirroring MMDA's published invariants.

## Sigma Rule — DNS/Proxy Access to Campaign Domains (Click Detection)

Catches the *engagement* branch (silent clickers) at DNS/proxy layer.

```yaml
title: DNS Access to NCAP-MMDA Smishing Look-Alike Domains
id: 7e5a4c8f-2d31-4a9b-b7c4-9f8e7d6c5b4a
status: experimental
description: >
  Detects DNS resolution / proxy access to domains associated with the
  NCAP-MMDA smishing campaign family (ncapmmda[.]skin and likely
  siblings). Watchlist-based; domains rotate, so pair with the TTP rule
  (8.1) and periodic enrichment.
references:
  - case PH-SMISH-2026-0813-NCAP-001
author: Vanguard (CTI)
date: 2026-08-13
logsource:
    category: dns
    product: generic
detection:
    selection_literal:
        query:
            - 'ncapmmda.skin'
    selection_pattern:
        query|contains|any:
            - 'ncapmmda'
            - 'ncap-mmda'
            - 'mmda-ncap'
            - 'ncapsettle'
    selection_tld_abuse:
        query|endswith:
            - '.skin'
            - '.top'
            - '.xyz'
            - '.icu'
            - '.cf'
    condition: selection_literal or selection_pattern
falsepositives:
    - '*.skin/.top/.xyz benign sites (pattern rule reduces noise; keep selection_literal only if you prefer zero-FP)'
    - Security-researcher lookups (exclude internal analyst CIDRs)
level: high
tags:
    - attack.initial-access
    - attack.t1566.002
    - attack.execution
    - attack.t1204.001
```

**Caution:** The `selection_tld_abuse` sub-rule is intentionally broad; leave it commented out (`#`) if you cannot tolerate its noise profile.

## YARA Rule — NCAP Phishing Page Content (for sandbox-captured pages only)

For analysts who capture the landing page in a sandbox or via urlscan/VT submissions. Do **not** run this against general web traffic; it is a content-matching rule for known campaign kits.

```yara
rule NCAP_MMDA_PhishingKit_HTML {
    meta:
        author = "Vanguard (CTI)"
        description = "Phishing HTML content impersonating MMDA NCAP portal (mayhulika). Case PH-SMISH-2026-0813-NCAP-001. Match on captured pages only."
        date = "2026-08-13"
        reference = "case PH-SMISH-2026-0813-NCAP-001"
        tlp = "CLEAR"
    strings:
        $a1 = "ncap" ascii wide nocase
        $a2 = "mmda" ascii wide nocase
        $a3 = "may huli ka" ascii wide nocase
        $a4 = "no contact apprehension" ascii wide nocase
        $b1 = "grace period" ascii wide nocase
        $b2 = "settle" ascii wide nocase
        $b3 = "violation" ascii wide nocase
        $b4 = "findings" ascii wide nocase
        $c1 = "<input" ascii wide nocase
        $c2 = "type=\"password\"" ascii wide nocase
        $c3 = "card" ascii wide nocase
        $c4 = "gcash" ascii wide nocase
        $c5 = "maya" ascii wide nocase
    condition:
        uint32(0) == 0x3C21444F or uint16(0) == 0x3C21 or (
            filesize > 2KB
            and 2 of ($a*)
            and 2 of ($b*)
            and 2 of ($c*)
        )
}
```

**False positives:** benign news articles and MMDA educational pages contain many of the same strings; the rule requires **both** an NCAP/MMDA identity **and** form/field strings (`$c*`) AND capture-context — apply only inside a capture pipeline, never as a network rule.

## Keyword / Watchlist (CSV-ready)

| Value | Type | Action | TTL |
|---|---|---|---|
| `ncapmmda.skin` | Domain | BLOCK (DNS + mail) | 30-90 days, re-verify |
| `ncapmmda` | Hostname pattern | MONITOR (wildcard in proxy logs) | 90 days |
| `el-mashharawi@live.de` | Sender alias | MONITOR (do not block live.de domain) | 90 days |
| `hxxps://ncapmmda[.]skin/` | URL | BLOCK (exact) | 30-90 days |
| NCAP + settlement + deadline (combined) | TTP pattern | ALERT (Sigma 8.1) | Persistent |
| `MMDA_NCAP` sender ≠ official sender | TTP pattern | ALERT on mismatch | Persistent |

## Platform-Specific Notes

- **Microsoft Sentinel / Defender:** translate 8.1 to KQL over `EmailEvents`/`EmailUrlInfo`; use `SenderFromAddress` regex and `UrlDomain` for 8.2.
- **Splunk:** map 8.1 over `index=email` with `| regex body="(NCAP|ncap).*settle"` style operators; 8.2 over DNS sourcetypes.
- **Chronicle/BigQuery:** UDM events `metadata.event_type = EMAIL`/`NETWORK_DNS` with `security_result` for watchlist join.

## Detection Gaps

1. **SMS payloads rarely reach corporate SIEMs** — the dominant blind spot; rely on user reporting + carrier filters (NTC/telco layer).
2. **Page content** is invisible at the perimeter; YARA only helps after capture — use urlscan/VT passive snapshots for triage.
3. **Domain rotation** makes artifact rules stale quickly; renew watchlists on a schedule (see TTL column).
